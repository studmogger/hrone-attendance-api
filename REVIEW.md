# REVIEW.md

## Defects Found in Starter `app/main.py`

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Naive datetime assumption without IST timezone conversion; extracts hours directly without timezone alignment and computes difference using integer division without proper floor logic across shift boundary. | Punch-in at `04:05:00Z` (which is `09:35 IST`) against shift `09:30` would compare UTC hour `4` with shift hour `9`, causing negative seconds or wildly inaccurate late minutes. | Parse punch-in instant into IST (`UTC+05:30`), align `shift_start` with attendance date in IST, evaluate strict `> 600s` grace period, and return `math.floor(diff_sec / 60)`. |
| 2 | `compute_work_hours` | Uses Python's built-in `round(..., 2)`, which implements banker's rounding (round-half-to-even) rather than half-up rounding. | Work duration with `.005` or similar fractional hours rounds down to even rather than up (violating R4). | Used `decimal.Decimal` with explicit `ROUND_HALF_UP` quantization to `0.01`. |
| 3 | `compute_overtime` | Returns any positive minutes (`max(0, ...)`) regardless of duration; does not enforce the 30-minute minimum threshold (R3); fails across midnight for overnight shifts. | 5 minutes overtime returned `5` instead of `0`; overnight shift ending on next calendar day evaluated against the start date. | Added overnight calendar day shift handling and strictly returned overtime only when `minutes >= 30`, otherwise `0`. |
| 4 | `GET /health` | Returns unconditional `{"status": "ok"}` without checking MongoDB connection. | Health probe returns 200 even when MongoDB is down or network connection is lost. | Executed `db.command("ping")` inside a `try/except` block and raised `HTTPException(503)` if MongoDB does not respond. |
| 5 | Startup Indexes | No database indexes created at application startup. | Missing unique constraints on `emp_code` and `(emp_code, date)`; list endpoints and explain plans trigger `COLLSCAN`. | Created idempotent indexes in FastAPI `lifespan` on `emp_code` (unique), `(emp_code, date)` (unique), and query/sort compound keys. |
| 6 | `POST /employees` | Check-then-insert race condition (`find_one` followed by `insert_one`). | Two concurrent requests with the same `emp_code` both pass `find_one` and insert duplicate employees. | Backed by a unique database index on `emp_code` and caught `DuplicateKeyError` to return HTTP 409. |
| 7 | `POST /employees` | Missing input validation for `shift_start != shift_end`, `emp_code` pattern (`^EMP\d{4,6}$`), and email format. | Client sending `shift_start: "09:30"` and `shift_end: "09:30"` was accepted with 201 instead of 422. | Added strict Pydantic model validation with regex patterns and model validator verifying `shift_start != shift_end`. |
| 8 | `POST /employees` | Boundary conversion error: stored BSON datetime returned in HTTP response instead of integer epoch milliseconds (`EpochMillis`). | Response schema validation failure where integer milliseconds were expected. | Converted `created_at` datetime to epoch milliseconds truncated to whole seconds at the response boundary. |
| 9 | `GET /employees` | Incorrect pagination skip formula: `skip = page * page_size`. | Requesting `page=1` skips the first `page_size` items (items 1–20 skipped entirely). | Fixed offset calculation to `skip = (page - 1) * page_size`. |
| 10 | `GET /employees` | `total` counts whole collection (`count_documents({})`) regardless of `department` query filter (violates R10). | Filtering by department returns `total` equal to total employee count rather than matching count. | Passed the query filter `q` into `db.employees.count_documents(q)`. |
| 11 | `GET /employees` | Does not sort by `emp_code` ascending. | Returned documents were in arbitrary natural database insertion order. | Added `.sort([("emp_code", ASCENDING)])` to the Mongo query cursor. |
| 12 | `POST /attendance/punch-in` | Check-then-insert race condition allows duplicate punch-ins for the same date under concurrency. | Parallel punch-in requests for the same employee on the same date both succeed or cause unhandled 500. | Relied on compound unique index `{"emp_code": 1, "date": 1}` and mapped `DuplicateKeyError` to HTTP 409. |
| 13 | `POST /attendance/punch-in` | Date determination ignores overnight shift rule (R1). Uses `ts.date().isoformat()`. | A 02:00 IST punch-in for a 22:00–06:00 overnight shift was tagged with today's date instead of the previous day's shift date. | Implemented `compute_attendance_date` to check if `punch_time < shift_end` on overnight shifts and assign previous day. |
| 14 | `POST /attendance/punch-in` | Unchecked employee lookup: crashes with `TypeError` if employee is not found. | Punch-in for an unknown employee threw an unhandled 500 error instead of 404. | Added explicit `if not emp: raise HTTPException(404, "Employee not found")`. |
| 15 | `GET /attendance` | Memory leak / crash: loads entire collection into Python memory with `list(db.attendance_logs.find(q))` and sorts in Python. | Severe latency and OOM failure on a dataset of 100,000 records. | Delegated sorting and pagination directly to MongoDB cursor via index scans (`.sort().skip().limit()`). |
| 16 | `GET /attendance` & `POST /attendance/punch-in` | Injected internal `id: str(_id)` into response body. | Violates OpenAPI schema (records have no `id` field; addressed by `emp_code` and `date`). | Omitted internal `_id` and excluded synthetic `id` field from response formatting. |

---

## Examined and Decided Was Not a Defect

1. **Storing Naive / UTC BSON datetimes in MongoDB**: Examined whether datetimes should be stored with timezone info inside MongoDB. BSON datetimes in MongoDB are inherently UTC timestamps. Storing UTC datetimes and performing IST boundary conversions in Python/pipelines adheres strictly to `DATA_MODEL.md`.
2. **Accepting `emp_code` as String without auto-generation**: Verified that `emp_code` is customer-generated and immutable per OpenAPI conventions, rather than auto-incrementing or ObjectId-based.
